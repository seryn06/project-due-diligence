# 项目背调 Skill（project-due-diligence）设计文档 v0.1

日期：2026-10-28
状态：已拍板，随建随验
初稿来源：`PlantPigAgent/docs/项目背调skill/v1.0.md`（方法论层），本文档为其可执行化设计。

## 0. 定位

在科研项目正式开始之前，系统性地调查领域现状、关键文献、已有方案、未解决问题、潜在创新点和实施风险，产出**有文献证据支撑、可指导立项决策**的背调报告。

它不是文献总结工具。区别由四个机制承载（见 §1），其中反证强制与决策件强制由 `gate.py` 机械执法，不依赖模型自觉。

## 1. 与文献总结工具的四个机制性区别

1. **组织骨架 = 问题树，不是论文列表。** P1 把项目拆成问题树（节点带稳定 ID），此后每篇入库文献必须挂到至少一个问题节点；不回答任何问题的文献剔除，没有证据的问题节点暴露为"未覆盖"。检索停止标准挂在树上（每个核心问题有直接证据 + 新一轮检索不再产生新主题），不是"读了 N 篇"。
2. **检索主动找反证。** 五条检索线中"反证与竞争路线"是结构性配置：对每个候选方向必须执行"最近先例"专查 + 负面结果专查。Gap Ledger 里 counter_evidence 为空的缺口 status 一律不得标"已确认"——由 gate 机械校验。
3. **知识形态 = 三台账 + 极性，不是叙述文本。** 每个事实主张是 Evidence Ledger 一条记录：paper_id + 原文引文 + 位置 + 极性（支持/反驳/混合）+ 证据类型（实验结果/作者自述/跨论文综合/推断）。痛点章节强制三分类：已证实问题 / 作者自述局限 / 综合推断。
4. **输出 = 决策件，不是理解。** 创新性审计三分法（已有工作已覆盖 / 可能差异待核验 / 证据不支持）、可行性风险清单、最小可行实验、终止条件。报告 11 章中 7 章是决策件；缺 gap_ledger / novelty_audit / feasibility 任何一件，运行不得标记完成。

## 3. 运行模型：七阶段状态机

- **触发**："帮我做 X 的立项背调"或 `/project-due-diligence`。
- **P0（交互）**：项目简报访谈——项目描述、深度档、时间范围、语言、资源约束 → `project_brief.md`。
- **P1 理解**：解析项目、拆问题树 → `question_tree.md`。
- **P2 检索计划**：核心问题 × 五条检索线查询矩阵 → `search_protocol.md`。
- **P3 搜集 + L1 筛选**：多源检索、去重、摘要批筛 → `search_log.json` + `catalog.json`。
- **P4 L2 精读**：核心论文逐篇卡片 → `paper_notes/`；最接近工作 L3 深读。
- **P5 综合**：跨论文对比、路线图、缺口 → `evidence.json` + `gaps.json` + `research_map.md`。
- **P6 审计**：反证专查、创新性审计 → `novelty_audit.md`。
- **P7 报告**：11 章报告 + 可行性 + 路线图。
- **`state.json`**：当前阶段、gate 结果、豁免登记、决策日志；跨会话可恢复（续跑时读取接着干）。
- **自治边界**：P0/P1、P7 与用户交互；P2–P6 自治推进，只在需拍板事项（如检索饱和是否停）回询。

### 深度档配额（defaults，references/search-strategy.md 中可改）

| 档 | 核心问题 | 候选文献 | L2 精读 | L3 深读 | 产出 |
|---|---|---|---|---|---|
| 快速预调研 | ≥3 | ~30 | 5 | 0 | 短报告 + 目录 + 缺口简表 |
| 标准 | ≥5 | 80–150 | 10–15 | 2–3 | 全套台账 + 11 章报告 |
| 深入 | ≥8 | 200+ | 20+ | 5+ | 全套 + 深度创新审计 |

## 4. 数据结构（全部 JSON，人类视图由 render_report.py 渲染）

| 文件 | 内容 | 关键字段 |
|---|---|---|
| `question_tree.md` | 问题树 | 节点 ID（Q1、Q1.2…）、每核心问题立项理由 |
| `catalog.json` | 文献目录 | paper_id、doi、title、year、paper_type、venue、**question_ids**（必填，gate 执法点）、source_url、access_status（仅摘要/全文可读/无法获取）、relevance、reading_status、reading_level（L1/L2/L3）、include_reason/exclude_reason |
| `evidence.json` | 证据台账 | claim_id、**question_id**、paper_id、claim、evidence_quote、location、evidence_type、polarity（支持/反驳/混合）、confidence（分项：直接性/设计合理性/可复现性/独立验证） |
| `gaps.json` | 缺口台账 | gap_id、gap_statement、question_id、supporting_evidence[]、counter_evidence[]、existing_solutions、gap_type、research_question、validation_plan、status（已确认/待验证/证据冲突/已解决） |
| `search_log.json` | 检索留痕 | 时间戳、source、query、filters、path（五线之一）、question_id、purpose、result_count、kept_count |
| `state.json` | 运行状态 | phase、gate 结果、waivers[]、决策日志 |

status=已确认 的机械前置条件（G5 执法）：反证查询已在 search_log 真实执行 + ≥2 独立来源支撑。
confidence 不是单一 0–100 分，而是分项评价（见 references/evidence-grading.md）。

## 5. 检索层

### 四源分工

| 脚本 | 职责 | 要点 |
|---|---|---|
| search_openalex.py | 主发现：关键词/语义检索、年份/类型过滤、引用数排序、游标翻页 | 免 key；mailto 进 polite pool |
| search_s2.py | 引文扩展：种子论文 references + citations 双向 | 免 key 限速，429 指数退避；S2_API_KEY 可选 |
| search_epmc.py | 生命科学补充 + 开放全文 | 植物/生信项目必走 |
| search_arxiv.py | AI/CS 预印本 | LLM/评测类领域主力源 |

统一记录形状（归一化后）：`source, source_id, doi, title, year, authors, venue, abstract, citation_count, oa_url, paper_type`。

### 五条检索线

综述检索 / 奠基工作检索 / 前沿工作检索 / 引文追踪 / **反证与竞争路线检索**。每条查询进 search_log 必带 `path` + `question_id` + `purpose`；反证线在 P2 计划中显式排定，非顺手。

### 饱和判断机械化

每轮检索后脚本统计：新增文献数、新增问题树节点数、新高相关论文数。连续一轮新增主题节点 = 0 且新论文 < 阈值 → 报告饱和，agent 决定是否停。

### Token 管理

候选摘要分批组装 digest（每批 ~20 篇），agent 按批 L1 筛选，每篇 include/exclude + 一句理由，不逐篇往返。

### 全文获取（可选增强）

探测到 scansci-pdf MCP 则为 L2/L3 论文下 PDF 入 run 目录；否则纯摘要推进，access_status 如实标注，报告声明"覆盖基于摘要级证据"。降级诚实。

## 6. 质量门 gate.py（核心 IP）

`gate.py check <phase>` 逐条校验 run 目录；输出每规则 pass/fail + 具体违规（文件+记录 ID）。

| 门 | 出口 | 规则要点 |
|---|---|---|
| G1 | P1 | 问题树节点全带 ID；核心问题数达档位下限；每个核心问题有理由；project_brief 字段齐 |
| G2 | P2 | 检索矩阵（核心问题 × 五线）每交叉格 ≥1 查询；同义词组已生成；查询带日期落库 |
| G3 | P3 | 目录已去重；每条挂问题节点 + access_status；档位配额达标（标准档 ≥3 综述）；include/exclude 全有理由；search_log 与 protocol 对得上 |
| G4 | P4 | L2 卡片字段完整（任务/方法/数据集/基线/指标/结果/局限/引文+位置）；L3 有对比表行；**DOI 打伪**：抽样 Crossref 验证 DOI 真实且标题匹配 |
| G5 | P5 | 每缺口 ≥1 可解析支撑证据；反证查询按 question_id 反查 search_log 真实存在；已确认 = 反证已查 + ≥2 独立来源；痛点三分类挂证据 |
| G6 | P6 | 每候选方向有审计条目（子主张拆解、最近先例查询组、三分法归类）；未查先例的方向直接 fail |
| G7 | P7 | 报告 11 章非空；报告引用全部可解析到 catalog paper_id；执行摘要主张挂 evidence_id；覆盖度声明在场；全部豁免进局限性章节 |

**豁免机制**：`gate.py waive <rule> --reason` 登记 state.json；后续检查放行但强制进报告局限性章节。门槛不死锁，放水必留痕。

`gate.py status` 输出运行全景。

## 7. 报告模板（11 章）

1. Executive Summary：领域现状、项目价值、主要风险、建议
2. Project Decomposition：目标、核心研究问题、范围边界
3. Literature Search Protocol：数据源、检索式、时间范围、筛选规则、**覆盖限制与豁免**
4. State of the Art：脉络、主要路线、代表性工作、研究地图
5. Pain Points：三分类（已证实 / 作者自述 / 综合推断）
6. Gap Ledger：缺口、支持证据、反证、验证状态
7. Novelty Audit：与最近先例逐项对比，三分法
8. Candidate Research Directions：方向、假设、路线、实验设计、预期贡献
9. Feasibility & Risk：数据、算力、工程、验证难度、失败模式
10. Recommended Roadmap：优先级、最小可行实验、里程碑、停止条件
11. Evidence Appendix：文献目录、证据台账、检索日志、待核验事项

方向排序按研究价值/创新证据/可行性/验证成本/影响维度，明确标注为辅助判断的主观评分，不包装成客观结论。

`render_report.py`：读台账填充模板 + 引用一致性检查（报告中每个 paper_id 引用必须存在于 catalog）。

## 8. 容错与降级

- API 不可用/限速：指数退避 → 跳过该源并在 search_log 记录，报告声明哪些源不可用。
- 无全文：L1-only 推进，access_status 如实标注。
- 冷门领域配额无法满足：豁免机制登记，进报告局限性。
- 会话中断：state.json 恢复续跑。
- 编造引用防线：G4 DOI 打伪（Crossref 抽样验证）+ G7 引用一致性。

## 9. 测试与验收

- **单元测试（unittest，零依赖）**：dedup（DOI/标题变体）、gate 全规则（fixture run 目录 pass/fail）、记录归一化、饱和度计算。
- **API 冒烟**：四源各真实调一次（限额内），验证解析与退避。
- **试点验收**：AIQA 多智能体评测领域，标准档跑全流程，对照 10-28 人工写的 v1.1 方案（六臂矩阵）：
  - 文献召回：人工已知的关键评测文献是否被发现；
  - 缺口质量：gap ledger 与六臂设计动机的吻合度；
  - 创新审计：是否找到最近先例、有无误报创新；
  - 人工复核记录进 docs/。
- 通过标准：gate 全绿（含豁免均有理由）+ 人工对照无重大遗漏（关键文献召回 ≥80%）。
