# 报告撰写指南（P7 加载）——逐章怎么写、好坏对照

> 本指南的存在理由：三次真实运行中报告两次被用户判"简略"。根因不是字数，而是
> 没有把台账里的具体事实（数字/机制/对照）写进正文。以下每章给出：写什么、怎么写、
> 常见失败模式、好例 vs 坏例（例子取自真实运行，可直接仿写）。

## 总则（写任何章节前读一遍）

1. **报告是台账的视图，不是独立的作文**——每个事实主张应能在 evidence.json 找到条目，
   每个工作引用应是 catalog 里的 paper_id。写之前先重读 L2/L3 卡片与摘要汇编，把数字
   列成清单放在手边。
2. **数字优先**：一个百分比/样本量/成本倍数比三句定性描述更有信息量。没有数字的
   段落问自己：摘要里真的没有数字吗？
3. **每个工作至少一句实质内容**："X 做了 Y"不算实质，"X 用 Z 方法在 N 个样本上发现
   效应为 D，含义是 W"才算。
4. **表格不算分析**：G7.6 明确表格/注释不计入正文深度。表格呈现结构，正文讲机制与含义，
   两者都要。

## §1 Executive Summary

**写什么**：领域正在发生什么（2-3 个转折/主线，各带证据号）→ 对本项目的判定（值不值得做、
空间在哪）→ 主要风险 → 建议。
**失败模式**：只写结论不写依据；转折写成"领域发展很快"式空话。
**好例**（真实运行摘录）：
> **转折三：评测的"评测"成为一级问题。** 四大工具调用基准 496 条专家复核发现 **18.5% 的
> evaluator-人失配率**，一个基准 23 次重跑分数漂移 18.9pp（57.9%→76.8%）足以改变排行榜
> 结论 (E08)；多信号平均聚合产生"信任膨胀"——HELM 榜 54 个模型按均分与按最弱链排序的
> top-5 **完全不重叠** (E06)。

**坏例**：`> 工具调用基准的评测存在一些问题，多篇论文指出了评测器的缺陷。`（无数字、无机制、无证据号）

## §2 项目分解

问题树六问（或 N 问）× 每问一句话答案 + 答案所在章节的对照表。边界条件写清楚（做什么/不做什么）。

## §3 检索协议与覆盖限制

统计块由 render 生成；人工部分写三件事：执行概况（多少查询/降级情况）、筛选规则、
**覆盖限制诚实清单**（哪些源失败、摘要级证据声明、与相关 run 的重合度若有）。
失败模式：把覆盖限制写成一句"覆盖可能不全"——要具体到哪条线、什么原因、影响什么结论。

## §4 研究现状（最重的章节）

**结构**：按支线组织（每支线 = 一条演化逻辑，不是一类论文）；每支线内：
时间线（2-4 个阶段）→ 逐工作讨论 → 支线小结判断（"这条线到哪了、空白在哪"）。

**逐工作讨论模板**：`[Pxxx]（年份）用 {方法} 在 {数据/规模} 上发现 {具体结果含数字}；
含义/局限 {一句}`。

**好例**：
> BenchAgent [P128]（2026，GPT-4.1、10 基准、3,302 实例/配置/轮、3 轮重复）——六配置中
> 仅 EvoAgent（79.70% vs Core 76.65%，三轮全胜）稳定胜出；**成本侧惊人**：LLM-Debate 在
> HumanEval +9.67pp 但 pooled -1.96pp、耗 1.39× token；ChatEval 在 IFEval +22.25pp 但
> pooled 落后、耗 **4.34× token**。

**坏例**：`> BenchAgent 比较了多种多智能体配置与单agent的效果。[P128]`（复述标题）

**多工作对比**：同支线 ≥3 个可比工作时上对比表（维度=各工作控制了什么/场景/发现），
表后必须有一段正文讲"表里看出的模式"。

## §5 痛点分析

三分类铁律（已证实/作者自述/综合推断）不变；每条已证实痛点写全四件：
**现象 → 证据链（跨域独立印证，每个带 Exx）→ 规模/数字 → 对本项目的含义**。
"含义"句是新手最容易漏的——它把文献痛点翻译成项目决策输入。

## §6/§7 缺口与审计

表格 render 生成；正文逐条/逐方向解读，回答：为什么这条算缺口（不是"别人没做"而是
"证据链显示X已证实而Y未解决"）、最强/最弱在哪、对方向的直接指向。
§7 必须有检索范围声明（查了什么/没查什么/未检出≠不存在）。

## §8 候选研究方向（决策核心）

每方向六件套：**定位（一句话）/ 科学假设 / 实验协议（步骤级：对象、样本量、控制、
统计方法）/ 先例对照表（维度×先例，空位列=你的差异化）/ 基线与指标 / 风险与回退**。
协议写到"另一个人能照着跑"的程度；先例对照表是审稿人视角的 preemptive defense。
排序给一句主观性声明。

## §9 可行性与风险

一切数字化：人时（标注量×分钟）、token（量级+判官单列）、工程量（人月）、
风险表（概率/影响/缓解三列，每风险一条缓解）。失败模式："成本较高"——较高是多少？

## §10 推荐路线图

周级表格 + **排期逻辑成文一段**（为什么这个顺序、什么并行、前置依赖是什么）+
每方向终止条件。排期逻辑是 G7.6 抓过的点：只有表格没有论述=没想清楚为什么这么排。

## §11 证据附录

catalog 表 render 生成；人工部分写**待核验清单**：摘要缺失的论文、依赖单一来源的结论、
建议全文复核的先例清单。这份清单是下一轮工作的输入。
