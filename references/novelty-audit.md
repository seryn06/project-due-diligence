# 创新性审计细则（P6 加载）

## 流程（每个候选方向）

1. **拆子主张**：方向的表述拆成可独立检验的子主张，按四类分：
   - 架构类：用了某种结构/机制（如"多智能体协作"）
   - 数据类：覆盖某种数据/语言/物种（如"跨语言证据一致性"）
   - 评估类：用了某种评测方式（如"端到端 vs 分组件归因"）
   - 科学问题类：回答了某个未解问题
2. **最近先例专查**（每个子主张至少一条查询，path=反证）：
   `子主张核心词 + 同义词 + (already / proposed / solved / via / using)`
   检索目标不是"有没有相关论文"而是"有没有做过同一件事"。
3. **三分法归类**（每个子主张）：
   - 已覆盖：先例的目标+方法+评估三要素与本主张实质重合（引用先例 paper_id）
   - 可能差异待核验：目标或评估有实质差异，但差异的价值未经验证（写明差异点 + 最小验证实验）
   - 证据不支持：先例已证明该差异无效/该路线已被否定（引用证据）
4. **写检索范围声明**：审计结论必须附"查了什么（源×查询×日期）"；检索无先例 ≠ 无先例。

## 反 checklist（这些结论形态是错的）

- "该方向有创新性"（太宽，未拆解）
- "没有发现类似工作"（未声明检索范围）
- "我们的方法与 X 不同"（差异是否实质未论证）
- 把架构差异当科学贡献（先问：换成单 agent + 工具调用，预期优势还在吗？）

## 输出契约（novelty_audit.json）

每个方向：direction_id、statement、subclaims[]（claim/bucket/evidence_ids/prior_works）、
closest_prior_queries[]（指向 protocol 里 path=反证 且 status=已执行 的查询 qid——G6.2 机械校验）。

## 最小可行实验要求

每个"可能差异待核验"子主张必须给出：能推翻该主张的实验 + 判据（什么结果说明差异不存在）。
给不出 → 降级为"证据不支持"或回炉重拆。


## 完整走例（缩编自真实运行的 D1）

方向表述："agentic QA 评测有效性审计框架（三件套）"

1. **拆子主张**（四类各至少一条）：
   - 架构类：把三件审计手段组合为框架 → 可拆
   - 评估类：复执行存活率作为标准报告项 → 可拆
   - 数据/场景类：QA/RAG 场景适配 → 可拆
   - 科学问题类：评测分数作为"易腐知识主张"的实证基础 → 已有 [P145]，标已覆盖
2. **先例专查**（进协议 path=反证，执行后 G6.2 对账）：
   `evaluation validity audit benchmark evaluator verification reproducibility agent`
   ——命中 [P184] + 两篇新审计（Who Guards / Safety audit）→ "单做审计"子主张降为已覆盖
3. **三分法归类**：见 templates/zh/examples/example_gap_entry.md 的 D1 JSON——
   2 条已覆盖、2 条可能差异待核验、0 条证据不支持
4. **对照表**：五维（场景/evaluator校验/复执行/契约/工具化）× 三先例 + 本方向，
   空位列（QA 场景、三件套同时成立）即差异化主张
5. **检索范围声明**：本审计基于 OpenAlex 主源 43 条查询（2026-10-29）、arXiv 前沿降级
   换源、英文为主——未检出 QA 场景先例限于该范围

**失败模式复盘**：若第 2 步省略（不跑先例专查），第 3 步的"可能差异待核验"就是拍脑袋；
G6.2 拦的是这一步。若对照表省略，报告 §8 的差异化主张无从核对。
